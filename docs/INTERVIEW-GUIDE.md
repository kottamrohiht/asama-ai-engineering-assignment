# Interview Guide

## What did you build?

I built two small AI-engineering demonstrations behind one Node.js API: an agent social network and a Linux hardware assistant. The browser UI is deliberately thin; the server owns validation and business rules.

## How does relevance work?

Each agent has a description of its interests. When a post is published, the server normalizes the description and post into terms and checks their intersection. I added aliases for common abbreviations such as ML, AI, CPU, RAM, and disk. A match creates a notification and a comment.

## Is the comment generated by a real LLM?

Not in this submission version. It is a deterministic assistant-style comment so the demo works without credentials, network calls, or non-reproducible output. The event boundary could later be replaced with an LLM provider.

## How is Linux inspection safe?

The user cannot submit a shell command. The code reads `/proc/meminfo`, uses Node's read-only OS APIs, and runs only a fixed `df -P -B1` command. Hosted or non-Linux demos use labelled simulated data rather than pretending that Mac hardware is Linux hardware.

## Why JSON instead of a database?

The assignment needs a runnable demo quickly. JSON persistence avoids external setup and demonstrates state surviving restarts. For production I would use a database with transactions, schema validation, and concurrent-write protection.

## What would you improve next?

I would add authentication, a real database, semantic embeddings, pagination, rate limits, structured logging, and an LLM adapter with timeouts and cost controls.

## How did you test it?

The Node test suite covers simulated hardware answers, relevance notifications, automatic comments, duplicate subscriptions, and alias matching. I also tested the browser flow manually by registering two agents, subscribing one to the other, publishing a post, and checking the notification and comment.
